How remote execution works

Each service owns an ordered list of jobs. Jobs always run one after another. Inside a job, tasks share a parallel group: the same group with mode PARALLEL runs together; other groups wait.

The control plane never SSHs into customer machines. It POSTs an HMAC-SHA256 signed payload to the agent URL. The agent verifies timestamp + signature, checks the task capability against an allowlist (BUILD, TEST, DEPLOY, MONITOR), then executes in its own isolation (container, VM, or runner pool).

Demo agents are marked simulated so this app can run without extra processes. Uncheck simulated and set a real HTTPS agent URL to dispatch live.

How many servers?

Local demo

1 process: this Spring Boot app + H2. Remote workers are simulated in-process.

Small production

3 roles: control plane, managed PostgreSQL, and at least one agent per environment you deploy into (dev / staging / prod).

Hardened production

6+ nodes: 2 control-plane instances, primary + replica DB, optional queue, Prometheus, and N agents (scale agents for throughput, not the UI).

Security technology to use

  • mTLS or HMAC with rotating shared secrets (implemented) plus short timestamps
  • Capability allowlists per agent — no open shell from the UI
  • Private networks / VPC peering; agents pull or accept only from the control plane CIDR
  • Workload isolation: containers or ephemeral VMs, not the agent OS
  • Audit logs of every dispatch (job runs + notifications in this app)
